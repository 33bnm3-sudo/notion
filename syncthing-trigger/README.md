# Syncthing 동기화 트리거

일시정지해둔 Syncthing 기기를 원할 때 재개시키고, 폴더별로 100% 동기화될 때까지
기다렸다가 화면에서 바로 완료 여부를 확인할 수 있는 도구입니다. GUI로 직접
눌러도 되고, 나중에 다른 프로그램/스크립트가 끝난 뒤 자동으로 호출하도록
연결할 수도 있습니다.

## 필요한 것

- Syncthing이 이미 설치·설정돼서 폰 등 다른 기기와 페어링돼 있어야 합니다.
- **API 키**: 창을 열면 `%LOCALAPPDATA%\Syncthing\config.xml`에서 자동으로 찾아서 채워줍니다.
  (Syncthing을 표준 경로에 설치한 경우 기준. 안 채워지면 **Auto-detect** 버튼을 눌러
  다시 시도하거나, Syncthing 웹 GUI → 설정(Settings) → 일반(General) → API Key에서
  직접 복사해서 넣으면 됩니다.)
- **API URL**: 보통 `http://127.0.0.1:8384` (Syncthing GUI 기본 주소, 안 바꿨으면 그대로 씀).

## 실행 방법 (GUI)

1. `run.bat` 더블클릭 → API 키가 자동으로 채워져 있을 것 (아니면 Auto-detect 클릭
   또는 직접 입력, 한 번 입력하면 저장돼서 다음부터 자동 채워짐)
2. **Load Folders** 클릭 → 공유된 폴더가 하나씩 목록에 뜨고, 각 줄마다 현재
   동기화율(%)과 **Sync** 버튼이 있음
3. 동기화하고 싶은 폴더의 **Sync** 버튼 클릭 → 그 폴더를 공유하는 기기만 재개시키고,
   3초 간격으로 그 줄의 %가 갱신됨. 100%가 되면 버튼이 다시 "Sync"로 돌아오고
   %가 100%로 표시됨. 여러 폴더를 동시에 눌러도 각자 따로 진행됨

## 다른 작업이 끝난 뒤 자동으로 실행하기 (Silent 모드)

창 없이 조용히 실행하고 싶으면 이 스크립트를 그대로 호출하면 됩니다:

```
powershell -File Sync-Trigger.ps1 -ApiKey <API키> -Silent
```

- `-ApiUrl` 생략하면 `http://127.0.0.1:8384` 사용
- `-TimeoutMinutes` 로 최대 대기 시간 조절 (기본 30분)
- 종료 코드로 결과 확인 가능: `0` = 전부 동기화 완료, `1` = 시간 초과, `2` = 에러 (API 키 오류 등)
- 콘솔에 폴더별 진행률이 그대로 출력됨

예를 들어 다른 자동화 스크립트 맨 끝에 이렇게 붙이면, 그 작업이 끝나자마자 이
스크립트가 이어서 실행됩니다:

```powershell
# ... (다른 작업이 여기서 끝남) ...
& "C:\path\to\syncthing-trigger\Sync-Trigger.ps1" -ApiKey "xxxx" -Silent
```

## 동작 원리

- **API 키는 이 컴퓨터에 설치된 Syncthing 인스턴스 하나에만 해당합니다.** 폰이 여러 대
  붙어있어도 그건 다 이 하나의 API 키로 관리하는 "원격 기기"일 뿐, 폰마다 별도의
  API 키가 있는 게 아닙니다 - 그래서 이 컴퓨터의 `config.xml`만 읽으면 됩니다.
- **폴더 기준으로 동작합니다.** 폴더 하나가 여러 기기(폰 여러 대 등)와 공유돼 있으면, 그 폴더의 Sync 버튼은 **그 폴더를 공유하는 기기들만** 재개시키고, 완료율도 그 기기들 중 제일 안 된 기기 기준으로 계산합니다 — 관계없는 다른 폴더/기기는 건드리지 않습니다.
- Silent 모드(`-Silent`)는 예외적으로 **전체 기기를 한 번에 재개**시키고 모든 폴더가 끝날 때까지 기다립니다 (다른 작업 끝난 뒤 "전부 동기화"용으로 쓰는 상황을 가정).
- Resume은 **내 컴퓨터 쪽에서 본 기기 일시정지만 풉니다.** 폰 쪽 Syncthing 앱 자체가 꺼져 있거나 그쪽에서도 일시정지돼 있으면 재개 버튼을 눌러도 실제로 연결되진 않습니다 — 폰 앱이 켜져 있는 상태에서 쓰는 도구입니다.

## 검증 관련 참고

이 환경에서 실제 폰 대신, 로컬에 Syncthing 두 개를 띄워서(데스크톱 역할 + 폰
역할) 서로 페어링하고 폴더를 공유한 뒤 실제로 검증했습니다:

- 정상 상태에서 완료율 조회 (100%, needBytes=0)
- 기기를 일시정지하고 새 파일을 만든 뒤 완료율이 떨어지는 것 확인 (예: 26%, 56%, 72%)
- **폴더 단위 재개**(`/rest/system/resume?device=`)로 특정 기기만 재개 → 재연결 →
  그 폴더 완료율이 100%까지 올라가는 전체 흐름을 실제로 폴링해서 확인
- 잘못된 API 키를 넣었을 때 403이 오는 것과 에러 메시지 처리 확인
- `%LOCALAPPDATA%\Syncthing\config.xml` 자동 감지: 실제 Syncthing이 생성한 config.xml에서
  `<gui><apikey>` 값을 정확히 읽어오는 것, 그리고 파일이 없을 때 에러 없이 조용히
  실패(수동 입력으로 넘어감)하는 것 둘 다 확인

다만 GUI 부분(WinForms 창, 폴더 목록)은 이 환경이 리눅스 샌드박스라 실제로
띄워서 눌러보지는 못했습니다 — REST API를 호출하는 핵심 로직만 별도로 뽑아내서
검증했습니다. 처음 실행할 때 한 번 확인해보시는 걸 권장합니다.
