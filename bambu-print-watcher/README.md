# Bambu 프린터 출력 감시기

밤부랩 프린터가 로컬 와이파이로 직접 쏘는 상태 정보(MQTT)를 구독해서, **출력이 시작되면 콜백 하나, 끝나면(성공/실패 둘 다) 콜백 하나**를 호출하는 파이썬 스크립트입니다. **밤부 스튜디오(슬라이서 프로그램)는 전혀 필요 없습니다** — 프린터 본체에 직접 붙는 방식이라 밤부 스튜디오가 켜져있든 꺼져있든 상관없이 동작합니다.

카메라 켜기/끄기는 이미 만들어두신 Scrapy 기반 자동화가 있다고 하셔서, 그 연결 지점만 `watch.py`의 `on_print_started()` / `on_print_finished()` 함수에 TODO로 표시해뒀습니다. 실제로 그 자동화를 호출하는 코드는 넣지 않았어요 — 어떻게 실행되는지(커맨드? 웹훅?) 알려주시면 그 부분만 채워드릴게요.

## 필요한 것

```
pip install -r requirements.txt
```

## 연결 정보 3가지 찾는 법

**IP 주소, 시리얼 번호는 자동 검색이 가능합니다** (`discover.py`, 아래 참고). **액세스 코드만 수동으로 찾아야 합니다:**

- **액세스 코드**: 프린터 터치스크린 → 설정(기어 아이콘) → 네트워크/WLAN 항목에서 확인. LAN Only 모드를 켤 필요는 없습니다 — 액세스 코드만 있으면 클라우드 모드에서도 로컬 접속이 됩니다.
- IP/시리얼 번호도 수동으로 보고 싶으면 같은 화면이나 프린터 본체 스티커에서 확인 가능합니다.

### 왜 액세스 코드만 자동으로 못 찾나요

밤부 프린터는 5초마다 자기 정보(IP, 모델명, 이름, 시리얼번호)를 네트워크에 브로드캐스트로 알아서 뿌립니다(SSDP 방식, UDP 2021번 포트) — 밤부 스튜디오도 이걸 듣고 프린터 목록을 자동으로 채우는 겁니다. 근데 이 방송엔 **액세스 코드(비밀번호)가 의도적으로 빠져있어요** — 비밀번호를 전체 네트워크에 광고하면 보안 구멍이 되니까요. 그래서 그것만 프린터 화면에서 직접 봐야 합니다.

## 프린터 자동 검색

```
python discover.py --timeout 5
```

5초간 네트워크를 듣고, 발견된 프린터를 IP/시리얼/모델명/이름과 함께 JSON으로 출력합니다. 프린터가 여러 대면 전부 나옵니다. `bambu-print-watcher-ui`의 GUI에도 "Scan" 버튼으로 붙어있어서, 발견된 프린터를 목록에서 골라 선택하면 IP/시리얼이 자동으로 채워집니다.

**주의**: 같은 공유기/네트워크에 있어야 발견됩니다 — 다른 VLAN, 게스트 와이파이, 다른 서브넷에 있으면 브로드캐스트가 안 넘어와서 못 찾습니다 (밤부 스튜디오도 똑같은 제약이 있습니다).

## 빠른 연결 테스트 (코드 실행 전에)

`mosquitto_sub` 같은 MQTT 클라이언트가 있으면 먼저 원시 데이터가 오는지 확인해볼 수 있습니다:

```
mosquitto_sub -h <프린터IP> -p 8883 --cafile <(echo) --insecure -u bblp -P <액세스코드> -t "device/<시리얼번호>/report"
```

출력 상태가 바뀔 때마다 JSON이 계속 찍히면 정상입니다.

## 실행

```
python watch.py --host <프린터IP> --serial <시리얼번호> --access-code <액세스코드> -v
```

`-v`를 주면 상태가 바뀔 때마다(`gcode_state = RUNNING` 등) 로그가 찍혀서 디버깅하기 좋습니다.

## 동작 방식

- `device/{시리얼번호}/report` 토픽을 구독하면 프린터가 상태를 계속 밀어줍니다 (JSON, `print.gcode_state` 필드)
- 가능한 값: `IDLE`, `PREPARE`, `RUNNING`, `PAUSE`, `FINISH`, `FAILED`, `UNKNOWN` ([출처](https://github.com/BambuTools/bambulabs_api/blob/main/bambulabs_api/states_info.py))
- `RUNNING`으로 처음 들어가면 시작으로 간주 (일시정지 후 재개는 다시 시작으로 안 침)
- `FINISH` 또는 `FAILED`로 들어가면 종료로 간주 (실패한 출력도 카메라는 꺼야 하니까 둘 다 포함)
- TLS 인증서 검증은 꺼져 있습니다 — 프린터가 자체 서명 인증서를 쓰기 때문에 이건 이 기기들에 접속할 때 표준적인 방식입니다 (밤부랩 공식 문서/커뮤니티 통합 프로젝트 전부 동일)

## 검증 관련 참고

실제 프린터가 없어서 진짜 MQTT 연결/실제 브로드캐스트 수신까지는 테스트 못 했습니다. 대신:
- 상태 전환 판정 로직(`PrintStateTracker`)은 가짜 상태 시퀀스로 단위 테스트 돌려서 검증했고, 그 과정에서 실제 버그 하나(일시정지 후 재개를 다시 "시작"으로 잘못 세는 문제)를 잡아서 고쳤습니다
- MQTT 클라이언트 생성/인증/TLS 설정 코드는 실제로 실행해서 예외 없이 도는 것까지 확인했습니다 (연결 자체는 프린터가 없어서 안 해봄)
- JSON에서 `gcode_state` 뽑는 경로(`print.gcode_state`)는 커뮤니티 문서에 나온 실제 예시 JSON 구조를 그대로 따랐습니다
- `discover.py`는 실제로 소켓을 열어서 로컬호스트로 가짜 SSDP 패킷을 직접 쏴보고, 정상적으로 잡아내서 IP/시리얼/모델명/이름을 정확히 파싱하는 것까지 end-to-end로 검증했습니다 (소켓 바인딩, 수신, 파싱 전부 실제로 돌려봄). 다만 이건 제가 만든 가짜 패킷을 잡은 거고, **진짜 밤부 프린터가 보내는 패킷의 정확한 필드명이 문서와 100% 같은지는 확인 못 했습니다** — 처음 Scan 눌렀을 때 프린터가 안 나오면 알려주세요.

처음 실제 프린터로 연결하실 때, 출력 한 번 걸어보시면서 로그에 `RUNNING`/`FINISH`가 제대로 찍히는지 확인해봐 주세요.
